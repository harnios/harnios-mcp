# Repository working rules

- Never create a Git commit or push to a remote unless the user explicitly confirms that action in the current conversation.
- Before changing application code, inspect the relevant SpecKit artifacts (`spec.md`, `plan.md`, `tasks.md`, and contracts when applicable`). If the requested behavior is not covered, update or create the appropriate specification artifacts before implementing the code.
- Treat specification and implementation changes as separate reviewable steps: explain the proposed spec impact before making code changes when the impact is material.
